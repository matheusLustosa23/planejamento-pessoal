Como o companion virou um pacote

O servidor monta um arquivo com o código do companion, os devices baixam pela tailnet e instalam com o pip, e uma linha colada no Termux leva um celular do zero até conectado. Esta página mostra cada peça na ordem em que ela acontece.

1 · o formato

Um pacote Python é um zip com um nome combinado

O pip instala arquivos .whl (wheel). Por dentro, um wheel é um zip comum: o código, mais uma pasta …dist-info que diz ao pip o nome, a versão, as dependências e o hash de cada arquivo. Como o formato é simples, o servidor monta esse zip direto em Python, sem ferramenta de build. É o arquivo infrastructure/companion_pacote.py.

O _versao.py não existe no repositório. Ele é escrito só dentro do pacote, na hora de montar. Por isso o companion rodando do repo responde __version__ = "dev", e o instalado responde a versão de verdade.
2 · a montagem no servidor

Da pasta companion/ ao arquivo, em cinco passos

  1. Listar os arquivos

    Percorre a pasta companion/ do Windows e deixa de fora o que o device não usa: __pycache__, as 78 saudações gravadas em .wav (8,7 MB, só o modo de voz do desktop usa) e o logo grande (2,5 MB). O código já trata a falta deles: sem saudação, não toca; sem logo grande, usa o pequeno.

  2. Normalizar o texto

    O Git do Windows grava os arquivos com final de linha CRLF. Um .sh com \r quebra o bash do celular ($'\r': command not found). Todo .py/.sh/.txt/.md entra no pacote com LF. O .gitattributes novo também força LF nos .sh do repositório.

  3. Ordenar pelo caminho em texto

    O Windows ordena nomes sem diferenciar maiúsculas, e o README.md mudava de lugar. Com a ordem diferente, o hash saía diferente para o mesmo conteúdo. Agora a ordem é pelo texto do caminho, igual em qualquer sistema.

  4. Calcular a versão

    Versão = 1.0.0 + os 10 primeiros caracteres do sha256 de todo o conteúdo. Mudou um byte do companion, muda a versão; o mesmo conteúdo dá a mesma versão no note e no Windows (conferido: h7967c20566 nos dois).

  5. Escrever o zip

    Grava o código, o _versao.py e os metadados em data/companion_dist/. Se já existe um arquivo dessa versão, reaproveita; ao gerar um novo, apaga o antigo. Fica sempre uma versão só.

3 · o download

O servidor só é alcançável pela tailnet

O agente escuta no IP do Tailscale (100.79.27.100:8080). O Termux não cria uma VPN no Android: o tailscaled roda em modo userspace e oferece um proxy SOCKS5 em localhost:1055. Tudo que precisa falar com o servidor passa por esse proxy: o curl da instalação (--socks5-hostname), o connect e o download da atualização (SOCKS_PROXY no ~/.brazaia.env).

4 · a linha que vira arquivo

Como o echo cria o instalar.sh

O ops/companion_kit.py lê o instalar.sh (≈ 2,7 KB, várias linhas), codifica em base64 e imprime uma linha só:

$ echo IyEvZGF0YS9kYXRhL2NvbS50ZXJtdXgv… | base64 -d > ~/instalar.sh && bash ~/instalar.sh eyJzZXJ2aWRvciI6…

echo <texto>

Escreve o texto base64 na saída. Base64 representa qualquer conteúdo usando só letras, números, +, / e =: sem quebra de linha, sem acento e sem aspas que o terminal possa interpretar.

| base64 -d

O | (pipe) passa essa saída para o base64 -d, que decodifica de volta para os bytes originais: o script inteiro, com cada quebra de linha no lugar.

> ~/instalar.sh

Redireciona o resultado para um arquivo. É aqui que o texto "vira arquivo": os bytes decodificados são gravados em ~/instalar.sh, idênticos ao original.

&& bash ~/instalar.sh <KIT>

Se o arquivo foi gravado sem erro (&&), executa o script e passa o kit como argumento. O kit também é base64: um JSON com o servidor, o nome do device e a chave do Tailscale.

Por que não colar o script direto? A primeira versão colava várias linhas. Copiado do terminal do Windows, o texto pode levar CRLF, e o bash do Termux nem reconhece o fim do bloco. Em base64, a linha é igual em qualquer lugar: Windows, WhatsApp ou e-mail.

5 · a instalação

O que o instalar.sh faz, de 1/6 a 6/6

A ordem não é arbitrária: o servidor só é alcançável pela tailnet, então o Tailscale precisa subir antes do download do pacote.

  1. Pacotes do Termux

    Instala python, termux-api e curl, à vista e sem perguntas (dpkg confdef/confold). Na primeira versão, uma pergunta escondida do dpkg travava este passo.

  2. Baixar o Tailscale

    Lê o índice oficial (pkgs.tailscale.com/stable/?mode=json), pega o arquivo da arquitetura do celular (arm64) e coloca tailscale e tailscaled em ~/ts/bin. Se já existem, pula.

  3. Entrar na tailnet

    Sobe o tailscaled em modo userspace com o SOCKS em :1055 e roda tailscale up --auth-key com a chave do kit. Os dois rodam com PATH=/system/bin: com o PATH do Termux, o Tailscale acha o termux-clipboard-set e faz uma chamada que alguns Androids bloqueiam (SIGSYS, medido no celular novo com Android 15).

  4. Baixar o companion

    Pelo SOCKS: pergunta a versão em /versao e baixa o .whl para ~/.brazaia/pacote/.

  5. Instalar

    pip install "…whl[cli]". O pip lê o METADATA, baixa as dependências do PyPI pela internet normal, confere o RECORD e copia o código para site-packages/companion.

  6. Configurar e subir

    python -m companion.setup --kit: grava o ~/.brazaia.env (com permissão 600, porque tem a chave), copia os scripts de dentro do pacote para ~/.brazaia/, instala o boot e os jobs (watchdog e localização) e pede as permissões. No fim, o supervisor sobe o connect e o rastreador.

6 · a atualização

O device se atualiza quando conecta

No handshake, o "welcome" do servidor traz a versão atual do pacote. O connect compara com a sua e decide:

Se o download ou o pip falhar, o connect registra no log e continua na versão atual. O device nunca fica sem companion por causa de uma atualização.
